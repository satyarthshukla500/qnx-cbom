## Reading notes (my own words, no header text copied)
- Plugin entry: a plugin is a DLL named qcrypto-<name>.so exposing a qcrypto_plugin_ops_t
  (init / uninit / get_desc). In its init it calls register_algorithm() once per algorithm.
  Static helper lib: libqcrypto_pluginS.a (linked with --whole-archive per the docs).
- Algorithm object (qcrypto_algorithm_t) = free-text name (max 32 chars incl NUL) + a type
  + a union of ops tables. So NEW NAMES are open-ended, but the TYPE is a closed set of
  7 defines: QCRYPTO_DIGEST_TYPE, QCRYPTO_RNG_TYPE, QCRYPTO_KEYGEN_TYPE, QCRYPTO_CIPHER_TYPE,
  QCRYPTO_MAC_TYPE, QCRYPTO_KDF_TYPE, QCRYPTO_SIGNATURE_TYPE (QCRYPTO_MAX_TYPE ends the list).
- Signatures (ML-DSA, SLH-DSA): YES, fits. A plugin can register e.g. "ml-dsa-65" as
  QCRYPTO_SIGNATURE_TYPE with qcrypto_signature_ops_t (init/sign_oneshot/verify_oneshot/size),
  and a matching QCRYPTO_KEYGEN_TYPE entry. Key enums have escape hatches:
  qcrypto_key_alg_type_t has QCRYPTO_CUSTOM_KEY_ALG (=100 and up), qcrypto_key_type_t has
  QCRYPTO_CUSTOM_KEY, qcrypto_key_args_t has a 'private' void* member. Users reach it with
  qcrypto_keygen_request()/qcrypto_signature_request() by name. Not tested by running code yet.
- KEM (ML-KEM): NO native slot. There is no KEM / encapsulate / decapsulate type, and no
  key-agreement (derive / shared secret) call in the public API at all, even for ECDH/DH
  (a DH key alg enum exists but no derive op). A KEM could only be shoe-horned into another
  type (e.g. misuse the KDF or cipher ops), which an app would have to know about. A real KEM
  needs a new algorithm type that only QNX can add to libqcrypto.
- Config: no qcrypto.conf sample ships in the SDK or in ~/qnximg. Format from the SDK manual
  (qcrypto_configuration.html): one line per plugin "<plugin> tags=<tag>[,<tag>...]", top-down
  match, last line should be tags=*; default path /etc/qcrypto.conf, override via
  _CS_CONFIG_PATH or qcrypto_set_config_path(). Untagged requests use __progname as the tag.
- Shipped plugins documented: OpenSSL (qcrypto-openssl-3.so), Certicom, TomCrypt.
  OpenSSL plugin doc lists signatures rsa-*, dsa-*, ecdsa-*, eddsa-pure; no PQC.
